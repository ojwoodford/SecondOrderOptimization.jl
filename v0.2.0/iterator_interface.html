The Iterator Interface

An iterator is the algorithm inside each iteration of the optimization loop. The loop linearizes the objective at the current point, hands the linear system to the iterator, which chooses a step and a trial point, and then decides from the trial cost whether the run has converged. The four built-in iterators (:newton, :levenbergmarquardt, :levenbergmarquardt_dtd and :dogleg) are written against the interface described here, and so can yours: Writing Your Own Iterator works through an example.

The interface is the submodule SecondOrderOptimization.IteratorInterface:

using SecondOrderOptimization.IteratorInterface

Its functions belong to SecondOrderOptimization (two, systemeltype and dampingfloor, to DampedLinearSolve), so a method you add, written IteratorInterface.iterate!(...) = ..., extends the function the loop calls.

SecondOrderOptimization.IteratorInterface — Module
SecondOrderOptimization.IteratorInterface

The interface for writing an iterator: the methods an iterator defines (iteratorname, construct, reset!, iterate!, and optionally restrictedstep, triallinearization and linearize!), and the functions it calls on the loop's state data; and check_iterator, which checks an iterator against the contract. See the manual's page on the iterator interface.

What an iterator defines

An iterator is named by a symbol, :name, which selects it in OptimizationOptions(iterator = :name). It defines four methods, and may define three more:

  • iteratorname for StaticSymbol{:name} (required): its display name. Defining this method registers the symbol.
  • construct for StaticSymbol{:name} (required): builds the iterator's own data, its state between iterations, from the linear system. It may call similarstep for work vectors and TrialLinearization, and nothing else of the system.
  • reset! (required): restores that data to the state construct returned, so that a run with a reused OptimizationWorkspace repeats a first run.
  • iterate! (required): one iteration.
  • restrictedstep (optional, default false): whether the step last returned was held back by the iterator's safeguard.
  • triallinearization (optional, default nothing): the iterator's trial linearization, if it holds one.
  • linearize! (optional): the linearization at the point the loop moved to. The default uses the trial linearization when it is ready, and otherwise evaluates fdf!; override it only to do something else.
SecondOrderOptimization.iteratorname — Function
iteratorname(::StaticSymbol{:name}) -> String

The display name of the iterator selected by iterator = :name (show(result) prints it). Required: defining it registers the symbol, so that OptimizationOptions(iterator = :name) accepts it. Part of IteratorInterface.

SecondOrderOptimization.construct — Function
construct(::StaticSymbol{:name}, ls, callbackchangesstate::StaticBool) -> itdata

Returns the data of the iterator :name for a run on the linear system ls: the state it keeps between iterations. Required, one method per iterator. It may call similarstep(ls) for work vectors, and TrialLinearization(ls, callbackchangesstate), and nothing else of ls. Part of IteratorInterface.

SecondOrderOptimization.reset! — Function
reset!(itdata)

Restores the iterator's data to the state construct returned, so that a run with a reused OptimizationWorkspace repeats a first run. Required. Part of IteratorInterface.

SecondOrderOptimization.iterate! — Function
iterate!(itdata, data, f, fdf!, options) -> Float64

One iteration. Sets the trial point (settrial!) and leaves the step in getstep(data), and returns the cost at the trial point (NaN if the cost there is NaN); or LINSOLVER_FAILED when no solve succeeded; or NO_STEP when no finite step could be formed. f is the objective's cost function and fdf! its linearization, to be handed to the functions that evaluate them (trialcost!, linearizetrial!); options is the run's OptimizationOptions, of which an iterator reads options.dstep and options.reldcost, and hands options itself to solvestep!.

The loop moves to the returned point even if its cost is higher, keeping the best point itself; to reject a step, retry inside iterate!. Required. Part of IteratorInterface.

SecondOrderOptimization.restrictedstep — Function
restrictedstep(itdata) -> Bool

Whether the step last returned was held back by the iterator's safeguard (damping, a trust radius, a shifted solve) rather than being its model's minimiser. After an accepted restricted step the loop does not test reldcost or dstep, since the step is small because of the safeguard. Optional; the default is false. Part of IteratorInterface.

SecondOrderOptimization.triallinearization — Function
triallinearization(itdata) -> Union{TrialLinearization, Nothing}

The iterator's TrialLinearization, if it holds one, so that the default linearize! can swap in the linearization it made at an accepted trial point, and so that a run with a reused workspace can prepare its spare system. Optional; the default is nothing. Part of IteratorInterface.

SecondOrderOptimization.linearize! — Function
linearize!(itdata, data, fdf!) -> Float64

Linearizes the objective at the current point, the point the loop moved to, and returns the cost there. Optional: the default swaps in a trial linearization the iterator has ready (see triallinearization), and otherwise evaluates fdf! at the current point. Override it only to do something else, for example to return a cost the iterator has already computed by linearizetrial!. Part of IteratorInterface.

What iterate! returns

iterate!(itdata, data, f, fdf!, options) returns a Float64, one of:

  • the cost at the trial point, which it has set with settrial!, leaving the step it took in getstep(data);
  • LINSOLVER_FAILED, when no linear solve succeeded: the run stops with TERMINATION_LINSOLVER_FAILED;
  • NO_STEP, when no finite step could be formed, with no trial point or step set: the run stops with TERMINATION_COST_NAN, before the callback and the loop's step tests.

A trial point whose cost is NaN is returned as that cost, not as NO_STEP: the loop then moves there and tests the step as usual, and stops with TERMINATION_COST_NAN.

data is the loop's state. Its type and fields are internal: an iterator reads it, and changes it, only through the functions below. Of options, the run's OptimizationOptions, an iterator reads the fields dstep and reldcost (its smallest useful step, and the relative change in cost below which it may stop retrying), and hands options itself to solvestep!. Annotate f and fdf! with type parameters (f::F, fdf!::FDF ... where {F, FDF}): an iterator only passes them on, and without the parameters Julia does not specialise the method on them, so that each evaluation is a dynamic call that allocates.

What the loop does around iterate!

  • It moves to the returned point, even if its cost is higher, and keeps the best point itself, returning it at the end. An iterator that rejects a step (a damping or a trust region that a trial failed) retries inside iterate!, and returns the trial it settles on, accepted or not.
  • It undamps the system after iterate! returns a cost, before the callback, so that an iterator need not, and the callback sees the undamped system. An iterator that needs the undamped model within iterate! (to predict the change in cost of a damped step, say) calls undamp! itself.
  • It reads restrictedstep after an accepted step: a restricted step is small because of the iterator's safeguard, not because the run has converged, so the loop does not then test reldcost or dstep (it still tests absdcost).
  • It linearizes at the new point by linearize!, unless the run has stopped.
  • It counts and times each linear solve, cost and linearization through the functions that make them (solvestep!, trialcost!, linearizetrial!); an iterator calls f and fdf! only through those, so that the result's counts are right.

The functions an iterator calls

The linear system, the step and the costs:

SecondOrderOptimization.solvestep! — Function
solvestep!(data, options) -> Bool
solvestep!(data, options, λ)
solvestep!(data, options, λ, scaling)

Solves the linear system for the step with the run's linear solver, options.linsolver. The two-argument form solves the system as it is currently damped; the others first set the damping to λ (a multiple of the identity), or to λ times the diagonal scaling (Marquardt's form), which stays set until it is changed. On success writes the step, the negated solution, into getstep(data) and returns true; otherwise returns false, and the step's contents are undefined. Each call counts as one linear solve in the result, and is timed. Part of IteratorInterface.

SecondOrderOptimization.undamp! — Function
undamp!(data)

Sets the system's damping to zero, so that predictedchange and curvature use the undamped model. The loop undamps after each iteration. Part of IteratorInterface.

SecondOrderOptimization.getstep — Function
getstep(data) -> AbstractVector{Float64}

The step storage, which solvestep! writes. An iterator leaves the step it took here: the loop reads it after iterate!. Part of IteratorInterface.

SecondOrderOptimization.getgradient — Function
getgradient(data) -> AbstractVector{Float64}

The gradient at the current point. Read-only for an iterator. Part of IteratorInterface.

SecondOrderOptimization.predictedchange — Function
predictedchange(data, s) -> Float64

The change in cost the quadratic model predicts for the step s, gᵀs + ½ sᵀHs, on the undamped system (call undamp! first if the system is damped). Part of IteratorInterface.

SecondOrderOptimization.curvature — Function
curvature(data, v) -> Float64

The curvature of the model along v, vᵀHv (‖Jv‖² for a Jacobian system), undamped. Part of IteratorInterface.

SecondOrderOptimization.maxdiagonal — Function
maxdiagonal(data) -> Float64

The largest absolute diagonal entry of the system's matrix (of JᵀJ for a Jacobian system), or NaN if a diagonal entry is NaN. Part of IteratorInterface.

SecondOrderOptimization.getdiagonal! — Function
getdiagonal!(out, data) -> out

Writes the undamped diagonal of the system's matrix (the squared column norms of J for a Jacobian system) into out, a vector like the step, and returns it. Part of IteratorInterface.

SecondOrderOptimization.systemisfinite — Function
systemisfinite(data) -> Bool

Whether every entry of the system's matrix is finite. A failed solve of a non-finite matrix cannot be repaired by damping, so an iterator stops retrying. Part of IteratorInterface.

DampedLinearSolve.systemeltype — Method
systemeltype(data) -> Type

The element type of the linear system's matrix (Float64 or Float32). The step, the gradient and the costs are Float64 whatever it is. A method of DampedLinearSolve's systemeltype, re-exported by IteratorInterface.

DampedLinearSolve.dampingfloor — Method
dampingfloor(data) -> Float64

The linear solver's smallest useful relative damping: a positive-definite matrix damped by dampingfloor(data) * maxdiagonal(data) solves. A method of DampedLinearSolve's dampingfloor, re-exported by IteratorInterface.

SecondOrderOptimization.similarstep — Function
similarstep(ls) -> AbstractVector{Float64}

A new work vector like the step, for construct to allocate the iterator's data. Its contents are undefined. Part of IteratorInterface.

The trial point and its cost:

SecondOrderOptimization.getbestcost — Function
getbestcost(data) -> Float64

The lowest cost the run has reached. Part of IteratorInterface.

SecondOrderOptimization.settrial! — Function
settrial!(data)
settrial!(data, s)

Sets the trial point to the current point updated by the step s, getstep(data) by default. Part of IteratorInterface.

SecondOrderOptimization.trialcost! — Function
trialcost!(data, f) -> Float64
trialcost!(tl::TrialLinearization, data, f, fdf!, likely::Bool) -> Float64

The cost at the trial point. The first form evaluates f, counted and timed as a cost evaluation. The second, for an iterator that holds a TrialLinearization tl: if likely (the iterator expects to accept the trial point) and tl holds a spare system, the cost is computed by fdf!, linearizing at the trial point into the spare (counted and timed as a gradient evaluation), which is then ready for the next linearize!; otherwise by f, as the first form. Part of IteratorInterface.

SecondOrderOptimization.linearizetrial! — Function
linearizetrial!(data, fdf!) -> Float64

Linearizes the objective at the trial point into the current system, in place, and returns the cost there. Counted and timed as a gradient evaluation. For an iterator that always moves to its trial point: it then returns that cost from its own linearize! method. Part of IteratorInterface.

SecondOrderOptimization.LINSOLVER_FAILED — Constant
LINSOLVER_FAILED

The value iterate! returns when no linear solve succeeded: a NaN with its own bit pattern, which the loop recognises (compared with ===) and stops on, with TERMINATION_LINSOLVER_FAILED. Part of IteratorInterface.

SecondOrderOptimization.NO_STEP — Constant
NO_STEP

The value iterate! returns when no finite step could be formed (dogleg, when the curvature along the gradient is not finite), having set neither a trial point nor a step: a NaN with its own bit pattern, which the loop recognises (compared with ===) and stops on at once, with TERMINATION_COST_NAN, before the callback and the step tests. A NaN cost at a trial point the iterator did set is returned as itself, not as NO_STEP. Part of IteratorInterface.

Saving an evaluation: the trial linearization

An iterator that expects its trial point to be accepted can linearize there while it computes the cost: the linearization (the gradient and the Hessian, or the residual and the Jacobian) gives the cost too, so the iteration evaluates fdf! once instead of f and then fdf! at the next point. A TrialLinearization in the iterator's data holds a spare system for this. The iterator calls trialcost!(tl, data, f, fdf!, likely) for the cost of a trial, with likely its guess that the trial will be accepted (Levenberg–Marquardt and dogleg guess from the predicted reduction of their first trial); discardtrial! when it rejects that trial; and returns tl from triallinearization. The default linearize! then swaps the spare system in. Built with callbackchangesstate = true the component holds no spare and always evaluates f, since the callback may change the point or the cost after the trial.

SecondOrderOptimization.TrialLinearization — Type
TrialLinearization(ls, callbackchangesstate::StaticBool)

A component for an iterator's data that saves an evaluation: when the iterator expects its trial point to be accepted it linearizes there (trialcost! with likely = true), into a spare system, while computing the cost; the default linearize! then swaps that system in instead of linearizing again. Built in construct, from its arguments. With callbackchangesstate true it holds no spare (the callback may change the point or the cost after the trial) and always evaluates f. The iterator returns it from triallinearization, resets it in its reset! (reset!(tl)), and discards a trial it will not accept with discardtrial!. Part of IteratorInterface.

SecondOrderOptimization.discardtrial! — Function
discardtrial!(tl::TrialLinearization)

Marks the spare linearization as not ready: for a trial the iterator rejects, after a failed solve, and at the start of iterate!. Part of IteratorInterface.

An iterator that always moves to its trial point (Newton) has no need for the spare: it linearizes at the trial point into the current system by linearizetrial!, and returns that cost from its own linearize!.

Checking an iterator

check_iterator runs an iterator on problems of its own and checks the contract above, throwing an error that names the first requirement broken. Call it in your iterator's tests.

SecondOrderOptimization.check_iterator — Function
check_iterator(name::Symbol) -> true

Checks that the iterator registered as name meets the iterator contract, and returns true; otherwise throws an ErrorException whose message names the first requirement violated, the problem, and the iteration. It runs the iterator on problems of its own whose fdf! (and resjac!) returns exactly f(x): a convex quadratic, Rosenbrock, and a small least-squares fit as both a HessianObjective and a JacobianObjective, each with a static and a dense system, and with callbackchangesstate false and true. At every iteration it checks that

  1. the value iterate! returns is a Float64, and, when it is a cost (not NaN), that it is isequal to f at the trial point;
  2. the trial point is isequal to the current point updated by getstep(data);
  3. restrictedstep(itdata) is a Bool.

Requirement 4, that the system is undamped when the callback runs, is not checked: the loop undamps the system after iterate! returns, before the callback, so no iterator can break it. For each run it checks that

  1. on a problem whose Hessian is singular, and on one whose Hessian holds an Inf, the run ends without an exception (a step, LINSOLVER_FAILED or NO_STEP are all conforming);
  2. on a problem whose cost is NaN away from the start, the run ends without an exception;
  3. a second run on the same OptimizationWorkspace allocates nothing and repeats the first run's costs exactly (which tests reset!);
  4. the result's cost and gradient counts are the numbers of calls to f and to fdf! (or resjac!), so that the iterator evaluates them only through trialcost! and linearizetrial!. (The count of linear solves cannot be observed from outside the system, and is not checked.)

It is not called by optimize; call it in your iterator's tests. Part of IteratorInterface.
